02

四块内容

按你要求的四项拆分。每篇都按「能直接抄」的标准写，不写“建议配置”这种废话。

adb.md

adb 使用方法

这块表最耗时间的不是写代码，是把 adb 调通。

  • 息屏的表叫不醒：keyevent 224/26 全部无效
  • 可靠唤醒配方：battery set ac 1 + input 事件
  • 充电屏 SysUI.Charging 抢焦点怎么绕
  • 截图 1610 字节 = 纯黑，不是崩溃
  • 横滑撞系统手势、两次输入之间要 sleep
project-notes.md

项目经验

186×215 dp 的屏幕，所有“通用最佳实践”都得重算。

  • 完全自绘 View 的分层（View / Store / Loader / Api）
  • 解析函数写成 static，用真实 JSON 离线自测
  • 三层缓存：内存 90s / 磁盘 3MB / 网络
  • 分页：第一页往往不含“今天”
  • 惯性衰减 pow(0.93, dt/16)、防烧屏
caveats.md

注意事项

构建链每一环的参数与顺序，错一个就卡半小时。

  • aapt2 compile --no-crunch / link --java
  • javac -source 8 -target 8，org.json 不进 apk
  • zipalign 必须在签名之前
  • 清单：watch feature、portrait、NoActionBar
  • 窗口亮度 ≠ Settings.System 亮度
pitfalls.md

避坑点

20 条「症状 → 原因 → 解法」，按踩到的频率排序。

  • d8 直接 NPE → 换 tools/r8.jar
  • 上滑“弹簧回弹” → 速度符号写反
  • 底部圆点点不动 → 热区判定顺序
  • 无限滚动手感死 → hasMore 从没赋值
  • 未开赛详情空壳 → 改走赛前分析接口

03

构建链：五步，每一步都有坑

不用 Gradle 的代价是手动串五步；好处是全量构建 5 秒、产物 25 KB 起。

01
aapt2 compile
资源编译。加 --no-crunch：跳过 PNG 压缩，更快，且矢量图本来就不用压。 坑build.sh 存成 CRLF，bash 把 \r 当参数，报一串 unknown option。
02
aapt2 link
链接出 base.apk。--java $OUT/gen 生成 R.java，--min-sdk 26 --target-sdk 27。 坑漏了 --java，javac 阶段找不到 R。
03
javac
编 Java。-source 8 -target 8，classpath 只放 android.jar。 坑把 json.jar 塞进 apk classpath → 运行时类冲突，org.json 必须用系统的。
04
d8 → adddex
转 dex 并塞进 apk。JBR 没有 jar 工具，所以用 python zipfile 手写条目。 坑build-tools 33.0.2 自带 d8 直接 NPE → 换 tools/r8.jar。
05
zipalign → apksigner
对齐后签名。顺序不能反；apksigner.bat 必须给 Windows 原生 JAVA_HOME。 坑JAVA_HOME=/d/... 报 invalid directory，要 cygpath -w。

04

六个最贵的坑

完整 20 条在 references/pitfalls.md。这六条是排查成本最高的，每条都真的耗过时间。

息屏的表，input keyevent 叫不醒 #1

症状
截图永远是 1610 字节纯黑，App 明明在跑。
原因
mWakefulness=Asleep；224(WAKEUP) 与 26(POWER) 在这台机器上都不生效。
解法
dumpsys battery set ac 1 → sleep 2 → dumpsys battery unplug → 任意 input 事件；用完 dumpsys battery reset。

d8 直接抛 NPE #4

症状
堆栈指向匿名内部类，跟自己的代码毫无关系。
原因
build-tools 33.0.2 自带的 R8 3.3.20 解析不了现代 javac 的 class 文件。
解法
换更新的 tools/r8.jar，脚本里做 [ -f ] && D8JAR=... 优先级判断。

上滑时“弹簧一样往上弹” #7

症状
惯性滚动正常，松手瞬间往反方向弹一下。
原因
符号写反：next = (int)(sc - st[0])，速度方向被取反。
解法
改成 sc + st[0]。这类“手感代码”只能真机滑，读代码看不出来。

列表滑到底不再加载 #10

症状
没有新数据，底部“加载更多”提示也从不出现。
原因
Page.hasMore 定义了但从来没赋值，读它永远是 false。
解法
在组装列表的收尾处显式赋值，并以“拉回空页”作为 exhausted 依据。

未开赛比赛的详情接口返回空壳 #12

症状
/data 只有 8 KB，bouts_state 空数组，一张地图都没有。
原因
比赛还没打，逐图数据本来就不存在。
解法
降级去调赛前分析接口（analysis_v1），它有双方选手、地图胜率、交手记录。

冷启动白屏，弱网整屏报错 #14

症状
网络慢时打开就“无法连接”，昨天明明还能看。
原因
没有任何持久化，每次启动都必须联网成功才能画。
解法
加磁盘缓存层（Cache.java），顺序 内存 → 磁盘 → 网络，失败用上次数据并标“离线”。

06

怎么用

两种用法：给人看，或者直接喂给 agent。

① 作为 agent skill

  1. 把整个目录放进 skill 路径，SKILL.md 有 frontmatter，能被直接识别。
  2. agent 会先读 SKILL.md 的「硬性结论」，再按需展开 references。
  3. 写代码时直接 copy templates/，改包名和业务逻辑即可。

② 作为人读的手册

  1. 先看 README.md 的 30 秒上手，跑通空白工程。
  2. 卡住了按现象查 pitfalls.md，每条形如「症状 → 原因 → 解法」。
  3. 设计 UI 前先读 project-notes.md 的 186×215 dp 排版数学。

改名时三处要一起改，否则编译期就报错：AndroidManifest.xml 的 package、Main.java / WatchView.java 的 package 声明、以及 app/src/ 下的目录路径。
